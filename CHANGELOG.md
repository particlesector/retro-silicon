# Changelog

All notable changes to this project are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and component versions follow [Semantic Versioning](https://semver.org/).

## Unreleased

### Added

- `common/clock-enable`: a `held` output, high on each clock a due pulse waits on `hold`, for counting the clocks `hold` costs.
- `common/crc32`: CRC-32 (IEEE 802.3, as zlib), one byte per enabled clock.
- `common/uart`: 8N1 receiver and transmitter; back-to-back bytes take exactly 10 bit times.
- `common/fifo`: synchronous FIFO with a registered read port, inferred as block RAM.
- `common/por`: power-on reset.
- `systems/uart-echo`: UART link test, with a Tang Nano 20K build at 1.5 Mbaud.
- `harness`: link interface, bit-level UART models, CRC32, the echo test and its Verilator backend.
- CMake helpers, FuseSoC manifests for every component, and lint tests (Verilator, Yosys, FuseSoC).
- `debug/test-shell`: UART command engine with CRC-checked frames, retries, build ID, PING, INFO, PEEK and POKE.
- `systems/shell-ram`: the test shell with a scratch RAM, with a Tang Nano 20K build.
- `harness`: test-shell client, `FaultyLink` for fault injection, the shell test, and `SimLink` for any Verilated UART design.
- `testroms/`: manifest of NES test ROMs with SHA-256 sums and expected results, and a fetch script.
- `tools/mesen`: MesenCE Lua runner and checker for blargg-style test ROMs.
- `rs_build_id`: a build ID derived from a system's RTL.
- `cpu/6502`: NMOS 6502, cycle-exact on the bus, with the stable unofficial opcodes and optional NMOS decimal mode; checked against perfect6502 in lockstep, nestest and blargg's instr_test.
- `cmake/Perfect6502.cmake`: fetches perfect6502 at a pinned commit, with SHA-256 checks, for the CPU's lockstep test.
- `memory/sdram`: byte-port controller for a 2M x 32 SDR SDRAM such as the Tang Nano 20K's, with a timing-checking chip model for sim tests.
- `memory/sdram`: 16-bit chips and any geometry (`DQ_W`, `ROW_W`, `COL_W`), and two chips on one bus (`RANKS=2`, the second on CS high, as on MiSTer's dual-chip boards, with the byte masks on A11 and A12 too); `systems/shell-sdram` takes them, with a Tang Console 138K build for its 64 MB SDRAM module and the harness's SDRAM test over any size (`rig::SdramLayout`).
- `systems/nes`: `nes_sdram` takes the SDRAM's geometry and CHR's block RAM size; the Tang Console 138K's NES keeps PRG ROM in its SDRAM module and 256 KB of CHR in block RAM, so all 190 golden ROMs run on it (188 on block RAM). `harness`: `make_nes_x16_sim` and `make_nes_x16_hdmi_sim`, the 138K's NES on a model of each of the module's chips, in place of `make_nes_bram_hdmi_sim`.
- `systems/shell-sdram`: the test shell with the SDRAM, with a Tang Nano 20K build and the harness's SDRAM test.
- `systems/nes`: the CPU with RAM, PRG RAM and NROM PRG from SDRAM, run control, a reset-vector override, a stop-at-cycle register and a CRC of the CPU's bus; a Tang Nano 20K build; nestest passes on it with the CPU bench's trace CRC.
- `harness`: iNES parsing, the NES console client and nestest runner, and optional host timing jitter in `SimLink`.
- `debug/test-shell`: CRC command (protocol version 2), so the host can check an upload without reading it back; `Client::crc`, and `write` and `read` for any length.
- `video/ppu-2c02`: the NES's 2C02 PPU (NTSC), dot-exact, with MesenCE's timing, and a save-state port.
- `common/clock-enable`: a clock enable at NUM/DEN of the clock rate, exact on average.
- `debug/video-probe`: frame and line CRCs of a video stream, and line-by-line capture that holds the system.
- `cpu/6502`: a save-state port; `docs/conventions.md` describes the port every component with state gets.
- `systems/nes`: the PPU, OAM DMA, CHR ROM or RAM and nametable mirroring; the NTSC dot rate from 27 MHz with MesenCE's CPU/PPU alignment; stop at a frame count; frame and line CRCs; frame capture; CPU and PPU save-state access.
- `harness`: `nes::rom_test` and the golden frame CRCs from MesenCE (`golden/nes_frames_crc32.txt`) for 42 PPU test ROMs; CHR upload, frame CRCs and frame capture in `nes::Console`.
- `testroms/`: 40 more PPU test ROMs, and the `zeropage` and `frame` checks.
- `tools/mesen/frames.py`: golden frame CRCs and frame dumps from MesenCE; `tools/frame.py`: frame to PNG and frame diff.
- `memory/arbiter`: fixed-priority sharing of one byte-port memory among N clients.
- `memory/bram`: block RAM behind `memory/sdram`'s byte port.
- `common/save-state`: saves and loads a system's state by walking byte regions of its bus into a buffer.
- `common/crc32`: a save-state write, so a restored CRC carries on.
- `systems/nes`: save states (save at the next frame boundary, load, and the buffer through the shell), the system's own state words, and an unmirrored view of the nametable RAM; `nes_sdram` and `nes_bram` put memory behind it.
- `boards/tang-console-138k`: the Tang Console 138K, at 50 MHz, with uart-echo, shell-ram and the NES on block RAM.
- `harness`: `nes::Console::save_state` and `load_state`, `nes::state_test`, and the NES model on block RAM at 50 MHz (`make_nes_bram_sim`); `SimLink` takes the model's clock rate.
- `video/hdmi`: video timing and TMDS encoding for an HDMI output in DVI mode, 1280x720 at 60 Hz by default, with a C++ TMDS encoder and receiver model for tests.
- `video/line-scaler`: a source's frames on a display of another clock, scaled by a whole number through a ring of lines in block RAM, with the source kept in step with the display.
- `common/cdc`: a flip-flop synchronizer for signals from another clock domain.
- `video/ppu-2c02`: `ppu_2c02_rgb`, the 2C02's 512 colours as RGB, generated by `tools/gen_rgb.py` from a simulation of its composite signal.
- `common/crc32`: `W`, the bits taken each clock (8 by default).
- `systems/nes`: HDMI at 720p (`nes_video`): the picture three times its size, the system keeping pace with the display by waiting at each frame's end, and a CRC of a display frame's TMDS symbols for the shell (registers `3C`-`4D`, status bits 6 and 7).
- `boards/tang-nano-20k`: the NES with HDMI, its clocks from the PLL: 371.25 MHz for the serializers, 74.25 MHz for the pixels and 46.40625 MHz for the system.
- `boards/gowin`: `tmds_phy` (OSER10 serializers and LVDS outputs); `build.sh -k` constrains a clock the design makes; stand-ins for Gowin primitives for the lint tests, through `rs_component(... LINT ...)`.
- `harness`: `nes::hdmi_test`, the video registers in `nes::Console`, `make_nes_hdmi_sim` (the Tang Nano 20K's NES with both its clocks, decoded by a TMDS receiver in the tests), and golden video CRCs (`golden/nes_hdmi_crc32.txt`).
- `boards/pynq-z2`, the first board outside Gowin's family: a Zynq-7020 built with openXC7 through `boards/xilinx/build.sh`, with the UART echo, the test shell, and the NES on block RAM with HDMI at 720p; `rs_board_bitstream` takes `VENDOR xilinx`.
- `boards/xilinx`: `tmds_phy_xc7` (OSERDESE2 serializers and OBUFDS outputs), with a sim test of its channel order, and stand-ins for Xilinx primitives for the lint and sim tests.
- `testroms/`: 39 APU and timing ROMs, the NROM single-test versions of blargg's apu_test, cpu_interrupts_v2, instr_misc and instr_timing, his 2005 APU tests, sprdma_and_dmc_dma and apu_mixer, each confirmed to pass in MesenCE.
- `audio/apu-2a03`: the NES's 2A03 APU (NTSC), cycle-exact: pulse, triangle, noise and DMC channels and the frame counter, with a save-state port and a C++ model it matches cycle for cycle.
- `audio/apu-2a03`: `apu_mixer`, the 2A03's nonlinear mix in two tables, generated by `tools/gen_mixer.py`.
- `video/hdmi`: `AUDIO` mode: HDMI with data islands, 48 kHz stereo L-PCM, audio clock regeneration and the AVI and audio InfoFrames; `packet` flags packet symbols. `tmds_model.hpp` gains an HDMI sink's decoder that checks every packet.
- `systems/nes`: the sound as 48 kHz PCM through `apu_mixer` and `audio/resampler`, out over HDMI; the PCM CRC and count (registers `54` and `58`); the video CRC leaves the islands' packets out.
- `audio/apu-2a03`: the pulse channels' sweep targets are registered a clock behind, so the APU's longest path no longer limits a system's clock; its access inputs must be steady a clock before `ce`. On the Tang Nano 20K every placement seed tried now meets timing (52.8-60.3 MHz against 46.4; 46.0-55.1 before).
- `audio/resampler`: the average and the high-pass take a clock each (`valid` comes three clocks after the `ce`; `busy` covers the gap), so its multiply no longer limits a system: 139 MHz on the XC7Z020, from 42.
- `boards/gowin/build.sh`: without `-s`, tries seeds 1 to 8 and keeps the first that meets timing.
- `docs/timing.md`: every component's fastest clock and size on the GW2A, GW5A and XC7Z020, from `tools/timing/report.py`.
- `tools/timing/report.py` and `build/components.json` (written by CMake): each component's fastest clock, logic and critical path on the GW2A, GW5A and XC7Z020, placed in a wrapper that keeps every path between registers.
- `boards/xilinx/build.sh`: a placement that mixes clock edges in a slice, which openXC7 can't configure, tries the next seed.
- `systems/nes`: two standard controllers (`$4016`/`$4017`, as MesenCE models them) and an input player: a script of buttons by frame (`0x07000000`, registers `60`-`69`), or live buttons, applied at frames' ends; their state in save states, now 21,024 bytes.
- `harness`: `Console::set_input_script` and `set_live_input`; golden ROMs may carry an input script (`input=frame:buttons,...`), which `tools/mesen/frames.py` plays in MesenCE through `setInput` and `rom_test` plays on the input player. Scripted runs of Thwaite and Concentration Room match MesenCE's frames.
- `testroms/`: homebrew built from source at a pinned commit (a source with `git`, `commit` and `build`); Damian Yerrick's Thwaite and Concentration Room (GPL-3.0), checked at their title screens in the sim and on the boards. Golden frame paths now name their source folder.
- `cpu/6502`, `video/ppu-2c02`, `audio/apu-2a03`, `audio/resampler`, `systems/nes`: a `SAVE_STATE` parameter (default 1); 0 leaves out the save-state port's logic for a board short of logic. The Tang Nano 20K's NES builds with it off.
- `audio/resampler`: an audio level to signed 16-bit PCM at a lower rate (low-pass, decimation, DC block), in integer arithmetic, with a save-state port.
- `systems/nes`: the APU, its IRQ and `$4015`; one DMA unit for the DMC's and OAM's DMA, as MesenCE runs them; the APU's 17 state words and the audio CRC (register `50`) in save states, now 20,992 bytes; the channel levels on `a_` ports.
- `boards/gowin/build.sh -s` and `rs_board_bitstream(... SEED)`: a fixed placement seed. nextpnr doesn't check hold for Gowin parts, and some Tang Nano 20K placements that meet timing fail on the chip (with HDMI audio, seeds 2 and 3); its NES builds with seed 5.
- `harness`: the audio CRC (`Console::audio_crc`, `TestResult::audio_crc32`), checked by the save-state test and against `golden/nes_audio_crc32.txt`; 34 APU and timing ROMs in the sim tests.
- `systems/nes`: mappers (`nes_cart`): NROM, UxROM, CNROM, AxROM, MMC1 (with SUROM's 512 KB) and MMC3 (with its revision B IRQ), set up from the ROM's header by registers `2C`, `2D` and `70`, as MesenCE runs them; PRG RAM only if the ROM has it; the mapper's registers in save states, now 21,052 bytes; all of CHR's block RAM at `0x08000000`.
- `systems/nes`: CHR ROM from the board's memory (`CHR_EXT`, the Tang Nano 20K's SDRAM), interleaved so a 32-bit word holds both planes of two rows, prefetched a dot ahead through the mapper into a two-word cache; a dot waits for memory that's behind (a PRG read, a CHR word) instead of missing it.

- `testroms`: 72 more ROMs from nes-test-roms, the rest of it for the mappers the core has with an automatic result (181 in the manifest); `mesen`, what a frame-checked ROM shows in MesenCE. `harness/golden/nes_frames_crc32.txt`: 175 ROMs.

- The reset button: `soft_rst` on `cpu/6502`, `video/ppu-2c02` and `audio/apu-2a03`, as MesenCE's reset; `systems/nes` presses it at chosen frames (registers `90`-`97`); `harness`: `reset=` in the golden frames and `Console::set_reset_presses`; `tools/mesen`: MesenCE presses it 10 frames after a ROM asks ($81 at $6000). `testroms`: blargg's apu_reset and cpu_reset (189 ROMs).

- `debug/trace`: a trace buffer, the last 2^AW entries a system records, in byte-wide block RAM. `systems/nes`: the last 1024 CPU cycles' bus in it (window `0x09000000`, registers `88`-`8E`, `TRACE_AW`). `harness`: `Console::trace()`, and `nestest` checks the trace against nestest.log when given its path.

- `systems/nes`: `nes_axi`, the system with its memory behind an AXI port through `memory/cache` (the PYNQ-Z2's DDR3 through HP0); register `78` counts the clocks the dots waited for memory, and `7C` a memory cache's hits, misses and prefetches.
- `memory/port-cdc`: the byte port across two clock domains by toggles, for a memory on its own clock. The PYNQ-Z2's NES runs HP0 and its AXI bridge on the 74.25 MHz pixel clock (`nes_axi`'s `ASYNC`), and all 103 golden ROMs run from its DDR3. `boards/xilinx/build.sh`: a seed whose clock buffers the router can't reach is skipped, as one with mixed clock edges is.

### Fixed

- `systems/game-boy`: with the LCD off, a blank frame ends every 70,226 dots (70,225 at double speed), from power-up, the LCD going off or the last blank frame, as MesenCE's do: its dot count steps 2 at a time at normal speed and it sends one once the count is more than 70,224 past the last frame. At 70,224, each came 2 dots early, and games that keep the LCD off for long (A Bug's Life, Cyber Tiger, Pooh and Tigger's Hunny Safari) ended 1 or 2 frames ahead of MesenCE. `gameboy` has a `dbl_speed` output for it. `harness`: a test that a Color game's first two frames, in the boot ROM, end at MesenCE's dots.
- `systems/game-boy`: a reset zeroes the console's work RAM, video RAM, OAM, high RAM and the Color's palettes, a byte a clock through each memory's write port, from reset's rising edge for as many clocks as work RAM has bytes, with the new `clearing` output high until it's done; `gb_sys` doesn't run the system until then. MesenCE powers up with its RAM zeroed, and before, `rig-run` running one game after another on the same system started each with what the last one left, as the Atari 2600's RIOT did (above). The palettes cleared with `rst` before, every cell in one clock, which a RAM can't do; GowinSynthesis made them RAM anyway and dropped the clear without a warning, so on the Tang Console 138K a Color game started with the palettes the game before it left (Cubix after Crystalis, Spider-Man 2 after Speedy Gonzales differed from MesenCE, and matched when run alone or in the sim). `harness`: a test runs a ROM twice in one system that sums every RAM, then fills it.
- `systems/game-boy`: on the Color, WX = 166 is as any other WX: the window starts at x = 159 and doesn't carry on into the next line, and the Game Boy's early start one pixel sooner (WX = position + 6) doesn't happen, as in MesenCE and SameBoy (whose Game Boy quirks these are). Before, the Color took the Game Boy's, and Bionic Commando: Elite Forces, which sets WY = 143 and WX = 166, drew its window across the next frame's first line. `harness`: a test of WX = 166 on the Color, its pixels checked against both.
- `cpu/sm83`, `systems/game-boy`: STOP with the Color's speed switch armed switches the speed even with an interrupt pending (IE & IF), as MesenCE's and SameBoy's do; the CPU's new `stop_switch` input says a switch is armed. Before, STOP with an interrupt pending did nothing, and Turok: Rage Wars, which switches with one pending and then waits for double speed, hung with the LCD off. `harness`: a test that KEY1 reads $FE after such a STOP; `cpu/sm83`: a unit test of `stop_switch`.
- `audio/apu-gb`: the pulse channels' timers and duty positions are packed arrays, so that they stay registers: the reset and NR52's power-off clear both channels' in one clock, and GowinSynthesis made the unpacked arrays RAM, as it did the Game Boy's palettes.
- `systems/atari-2600`: FE (Activision) switches banks only when the access after `$01FE` carries an address's high byte (`$Fx` or `$Dx`), as Activision's patent and Gopher2600 have it. The reset's stack reads touch `$01FE` too, and with a vector whose low byte had D5 clear the cartridge started in bank 1 (The Activision Decathlon); `bank_fe` checks it.
- `systems/atari-2600`: the TIA, the RIOT and the paddles stay in reset through the CPU's 7-cycle reset sequence, so they start on its first fetch, as Stella's do. Started with the CPU, their counters ran 21 colour clocks ahead of Stella's: a cartridge that writes RSYNC before its first WSYNC (as one that clears the TIA counting down does) left the TIA's audio counter 21 colour clocks off the line for the rest of its run, and a few samples' sums differed from Stella's wherever it wrote a sound register between the two places (with the input player's fix below, all 40 of the 44 commercial 4 KB games whose sound differed that aren't paddle or keypad games now match).
- `systems/atari-2600`: `a2600_sys`'s input player applies a due entry at the next opcode fetch, not as the frame ends: Stella finishes the instruction a frame ends in before it takes input, so a game polling a switch (Space Tunnel waiting for Reset to go up) read the new pins one instruction early.
- `io/riot-6532`: a reset held for 32 clocks clears the RAM to 0, a word a clock, as Stella starts it. Before, a reset left the RAM as the last program had it, so `rig-run` running one cartridge after another on the same system started each with the last one's RAM: Chris's commercial games (Time Pilot's title, for one) differed from Stella's frame after another game, and matched when run alone. `a2600_sys` holds its reset far longer than 32 clocks while it loads a cartridge.
- `tools/stella`: `stella-frames` turns Stella's phosphor blending off for every cartridge. Stella 7.0's core applies its `stella_phosphor` option only when it changes after a game is loaded, so a cartridge whose entry in Stella's database turns phosphor on (flicker games such as Asteroids) still blended frames, and `stella-frames` stopped with "a colour not in the palette". The option now says `auto` while the game loads and `off` after, which the core applies before the first frame. Every golden list comes out the same.
- `systems/nes`: with CHR ROM in the board's memory (`CHR_EXT`), a dot now waits for its CHR word only when the word still isn't there as the dot must end (`clock_enable`'s `hold`), not from the moment it's missing. On the Tang Nano 20K a 256 KB CHR ROM's waits fall from about 13,800 clocks a frame to 1,100 (of 17,471 to spare keeping pace with 720p), and Super Mario Bros. 3's in World 1-1 from 15,800 to 2,400: it no longer slows down and loses its sound when the screen scrolls up. `mem_waits` (register 78) counts the clocks actually lost. Nothing the system does changes. `harness`: a test that the 20K's waits with CHR ROM in its SDRAM take at most a quarter of its spare time.
- `systems/atari-2600`: `a2600_video`'s sound comes at 48 kHz, 800 samples in every display frame, whatever length the cartridge's frames are: each frame's sound is resampled to 800 samples for each display frame the frame before took (its CPU cycles and the requests it missed), steered by the level of a 4,096-sample FIFO from which it goes to HDMI at exactly 48 kHz, starting with 2,048 waiting (the sound 43 ms behind the picture). At 800 samples per 262 lines, `tia_playfield`'s 263-line frames made 803 a display frame and `tia_audio`'s longer ones too many or too few, so the receiver's buffer filled or ran dry and it muted (heard on the 20K through the capture dongle). Register `46` counts the times it ran dry or dropped a sample while playing; `rig::a2600::hdmi_test` fails a run with any but the drain at its end.
- `systems/atari-2600`'s frame test checked a frame only when it ended at VSYNC: one Stella's frame manager ends by its line count, with VSYNC overdue, gave a CRC of 0. `tia_rsync`'s 351-line frames found it.
- `testroms`: Concentration Room rebuilds to its pinned SHA-256 from a fresh fetch: its title screen shows the build time (ca65's `.time`), so its build now fixes that at the time of the pinned build.
- `video/ppu-2c02`: the sprite pixel is taken by shifting the line buffer's bytes. GowinSynthesis (1.9.11.03) merged `sl_lo` and `sl_hi` into one register RAM and read the pair of bit-selects from the wrong bits, so on the Tang Console 138K a transparent sprite pixel read as opaque (a false sprite-0 hit); 8 test ROMs and the save-state round trip failed there. The RTL's behaviour is unchanged.
- `boards/tang-nano-20k`, `boards/pynq-z2`: the NES's dots run 2% faster than NTSC's (13/110 and 9/61 of the clock), so that keeping pace with the display it has room for memory waits: at NTSC's rate a frame took 99.84% of a 60 Hz display frame, and one that overran waited for the next, so busy games stuttered (Kirby's Adventure on the PYNQ-Z2). The NES waits at each frame's end, so it still makes 60 frames a second, with the same sound.
- `cpu/6502`: the unstable unofficial opcodes (XAA, LAX `#imm`, LAS, SHY, SHX, AHX, TAS) run as MesenCE runs them, instead of halting.
- `systems/nes`: a DMA's dummy cycles no longer clock the pads during a `$4016`/`$4017` read; only its halt cycle does, as on an NES.
- `video/ppu-2c02`: dot 0 of a visible line presents the pattern address of dot 339's nametable byte, so an MMC3 with the background at `$1000` doesn't count a second A12 rise in a line.
- `tools/mesen/frames.py`: MesenCE's battery saves are cleared before each run; a ROM with battery-backed PRG RAM got a different frame the second time.
- `testroms/manifest.toml`: blargg's all-in-one ROMs say they need MMC1, and `instr_misc` and `instr_timing` unstable opcodes.
- `video/line-scaler`: the ring is in memories of 8 bits or fewer, so no toolchain has to use block RAM parity bits; with openXC7 a 9-bit ring lost its ninth bit (the NES's emphasis) on a PYNQ-Z2.
- `memory/sdram`: a WRITE waits the whole of tRAS after its row opens. Its auto-precharge can start under a clock after it, so from about 40 MHz the precharge could come before tRAS.
